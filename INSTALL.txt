PEMF - Pirates! Expanded Modding Framework


INSTALLING
----------

1. Find your game folder - the one containing Pirates!.exe.

       GOG     C:\GOG Games\Sid Meier's Pirates\
       Steam   C:\Program Files (x86)\Steam\steamapps\common\Sid Meier's Pirates!\

   In Steam you can get there with:
       right-click the game -> Manage -> Browse local files

2. Copy everything from this archive into that folder.

   You should end up with version.dll and pemf_core.dll sitting beside
   Pirates!.exe, and a new PEMF folder next to them.

   *** WATCH OUT FOR THIS ONE ***

   Windows' own "Extract All" does NOT put the files where you point it. It
   creates a SUBFOLDER named after the zip and puts them in there, so you end
   up with:

       Sid Meier's Pirates!\PEMF-0.2.5\version.dll        <- wrong, does nothing

   instead of:

       Sid Meier's Pirates!\version.dll                   <- right

   If you are UPGRADING, this is worse than nothing: the old DLLs are still
   sitting in the game folder, so the game keeps running the OLD version while
   you are certain you installed the new one.

   The safe way is to open the zip, select all, and drag the files into the
   game folder - or extract anywhere you like and then move version.dll,
   pemf_core.dll and PEMF into place yourself.

3. Launch the game as you normally would.

That is all. The game executable is never modified.


UPGRADING FROM AN EARLIER VERSION
---------------------------------

Extract straight over the top. Your saves, your key bindings and your edited
.ini files are all left alone.

Both DLLs must come from the SAME zip. If they do not, pemf.log says so in
capitals on the third line - see below.


CHECKING IT WORKED
------------------

Two log files appear in the game folder the first time you run it, and which of
them turns up is the fastest way to tell what happened:

    pemf_proxy.log    written by version.dll, the moment Windows loads it
    pemf.log          written by pemf_core.dll, once PEMF is up

Both there, and PEMF is running. Only the first, and Windows loaded the mod but
something refused the core - the last line of pemf_proxy.log carries the error
number. NEITHER there, and version.dll was never loaded at all: the game did not
read the files you installed, and nothing of ours has run yet. That last case is
almost always the wrong folder - see docs/TROUBLESHOOTING.md.

Open pemf.log. The first lines tell you:

    - which version of PEMF is running, and when it was built
    - whether version.dll and pemf_core.dll are the same version
      (a line beginning "*** MIXED INSTALL" means they are not, and that
       you have the subfolder problem described above)
    - which build of the game was detected, and whether every engine
      address verified

If something is wrong it says so in plain English.


UNINSTALLING
------------

Delete version.dll, pemf_core.dll and the PEMF folder. Nothing else was
touched.

If you want your original key bindings back, PEMF saved them as
KeyMap.ini.pemf-backup, next to the KeyMap.ini it replaced. That is in your
Documents folder under My Games - and the folder name depends on which copy of
the game you own:

    Steam   My Documents\My Games\Sid Meier's Pirates!\
    GOG     My Documents\My Games\Sid Meier's Pirates\

Rename the backup over KeyMap.ini. (pemf.log names the folder PEMF chose, if
you are not sure which is yours.)


WHAT CHANGES IMMEDIATELY
------------------------

WASD steering, in every part of the game - sailing, ship battles, land
battles, duels, sneaking. Two keys had to move to make room:

    Attack ship   was 'a'   now 'f'     (same key as Fire in a sea battle)
    Quick save    was 'S'   now F5      (quick load is now F9)

If you installed an earlier version of PEMF, Attack was on Space for a while.
Space is the game's own "enter the nearest port" key, so attacking a ship near a
harbour docked you instead. Moving it to 'f' fixes that, and your KeyMap.ini is
rewritten once to pick the change up. Anything you rebind after that is yours
and stays; your pre-PEMF file is still in KeyMap.ini.pemf-backup.

While sailing, 'a' and 's' used to load and save the game as well as steer -- the
sailing view reads those two straight from the keyboard rather than from
KeyMap.ini, so rebinding them was never enough. Steering left could load your
last save and drop you in a port. That is fixed.

PEMF writes this once, keeps a backup, and never touches the file again - so
anything you rebind afterwards stays rebound.


PLAYING FALSE FLAG
------------------

    Ctrl+Shift+8    run up a different flag
    Ctrl+Shift+9    run your own colours back up
    Ctrl+Shift+0    write a report to pemf.log

Fly another nation's flag and a meter appears in the top right. It fills while
their ships and ports can see you, and empties in open water. Fill it and they
see through you - your reputation with them drops, your colours are struck, and
they send pirate-hunters after you.

Sail away and the trail goes cold. The further you get, the faster it cools.

Tuning lives in PEMF\suspicion.ini. It is commented, and a reinstall will not
overwrite one you have edited.


WEATHER
-------

Storms are drawn far heavier than the game ships them, they drift across the
map, and they have a sound that comes up as you close on one. This is on by
default; set enabled = 0 in PEMF\storms.ini to turn it off.

Optionally a storm can cost you a little cargo. That is OFF by default - set
cargoLoss = 1 if you want weather to be something you avoid.

Tuning lives in PEMF\storms.ini, commented throughout, and a reinstall will not
overwrite one you have edited. Start with stormScale, and raise stormHeight
whenever you raise it.


KNOWN ISSUE - ALT-TABBING QUICKLY
---------------------------------

Alt-tab out of the game and Windows starts putting your desktop back to its
normal resolution. That takes a moment. If you alt-tab BACK IN before it has
finished, the game can lock up on a black screen that sits over everything and
has to be force-closed.

Give it a second before you switch back and you will not see it.

If it does happen, you do not need to reboot:

    Ctrl+Shift+Esc  ->  find Pirates!.exe  ->  End task

Task Manager draws above the stuck window, so it will come to the front.

Playing in a window instead of full screen avoids this completely - the
graphics device is never taken away, so there is nothing to race.

This is being worked on. It is ours, not the game's: the stock game survives the
same test. What it is NOT is a risk to your saves - the game is stuck, not
writing anything.


REPORTING A PROBLEM
-------------------

Send pemf.log and pemf_proxy.log along with a sentence about what you were
doing. The logs are where everything useful is.

If neither file exists, say so - that is not a missing detail, it is the single
most useful thing you can tell us, and it points at a completely different
cause than a log full of errors does.


BOTH STORE VERSIONS ARE SUPPORTED
---------------------------------

GOG and Steam both work. The Steam executable is compressed on disk, so PEMF
waits for it to unpack before touching anything and verifies every address it
uses at runtime.

The Challenge Pack executable is a DIFFERENT build of the game and is not
supported. PEMF detects it and disables itself rather than risk your save.


LINUX, PROTON AND THE STEAM DECK
--------------------------------

Not tested by us, but one tester's report has been acted on and there are two
things you need to know.

Wine provides its own version.dll and prefers it over ours, so nothing of PEMF
loads and NO log file is written at all. Fix that in Steam with
right-click -> Properties -> Launch Options:

    WINEDLLOVERRIDES="version=n,b" %command%

Keep %command% on the end. Start the game, quit, and check for pemf_proxy.log
in the game folder.

Second: releases up to and including 0.2.6 were zipped in a way that Linux
unpacks as files literally named "PEMF\events\core_events.json" rather than as
folders. That is fixed from this release on. If you are on an older one, see
docs/TROUBLESHOOTING.md for a one-line command that repairs the tree.
